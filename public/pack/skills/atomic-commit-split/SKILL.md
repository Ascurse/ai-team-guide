# atomic-commit-split — разбивка изменений на коммиты по смыслу

Когда в рабочем дереве вперемешку лежат правки по нескольким бидам/задачам — осознанно нарезать их
на коммиты по логической границе, а не сваливать всё одним коммитом.

## Когда запускать

- После раунда работы через несколько бидов или субагентов — в diff смешаны разные смысловые блоки.
- Просьбы «собери коммиты по одному на бид», «закоммить двумя коммитами», «мои N файлов — отдельным коммитом».
- Любой момент коммита, когда изменения затрагивают **больше одной** задачи/фичи/области.

## Правило по умолчанию

Правки затрагивают **больше одного** бида/смысловой блока → **предложить разбивку**, не коммитить всё одним.
Затрагивают ровно один — коммить одним, разбивка не нужна.

## Шаги (не пропускать)

### 1. Посмотреть, что в дереве
`git status` + `git diff` (и staged). Понять, сколько разных смысловых блоков реально смешано.

### 2. Сгруппировать по границе
Кандидаты на границу, в порядке предпочтения:
- **один бид = один коммит** (основной случай);
- конкретные файлы отдельно от остального (например, «мои правки» vs автогенерённое/тулбар);
- по домену/фиче, если один бид разросся на несвязанные куски.

### 3. Предложить разбивку и дождаться подтверждения
Показать список: коммит → какие файлы/хунки → сообщение (по конвенции проекта, напр. `fix(education): …`).
Спорную гранулярность («одним или несколькими?») уточнить у пользователя — он задаёт нарезку.

### 4. Закоммитить по группам
`git add` точечно (пути или `-p` по хункам) на каждую группу → коммит с сообщением группы. Повторить.
Прогнать lint/build/test после коммитов (минимум — после всех), иначе пункт «Проверка» о самодостаточности
коммитов не подтверждён.

### 5. Пуш
После всех коммитов — пуш. Дальше по `beads-workflow` (мерж/закрытие бида) без изменений.

## Проверка (verification-before-completion)

- Каждый коммит самодостаточен: один смысловой блок, собирается и проходит тесты сам по себе.
- Ни один коммит не смешивает несвязанные биды/фичи.
- Сообщения по конвенции проекта; привязка к биду сохранена.

## Запреты

- Не коммитить всё одним коммитом, когда затронуто >1 бида, без явного согласия пользователя.
- Не `git add -A` вслепую, если дерево смешанное — добавлять точечно.
- Заменяет шаг коммита из `beads-workflow` (`git add -A && git commit`) именно в сценарии >1 бида/блока
  в дереве; вне этого сценария `beads-workflow` работает как обычно.
