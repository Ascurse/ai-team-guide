# План вертикальными срезами

Срез — это одно поведение, которое пользователь может увидеть, сквозь все слои: данные → API → UI → тест. Горизонтальный план («сначала все фильтры, потом эндпоинт, потом UI») откладывает первую проверку до конца и даёт больше всего переделок.

## Форма плана

```markdown
## Разведка (без правок)
- что найти в репо → какое решение от этого зависит

## Срез 1: <самый тонкий путь насквозь>
Поведение: <что увидит пользователь>
Файлы: <что меняется во всех слоях>
Проверка: `<команда>` → <ожидаемый результат>
Готово, когда: <наблюдаемый факт>

## Срез 2: <+ одно поведение поверх среза 1>
...

## Вопросы владельцу
- <решение> — по умолчанию: <что делаю, если ответа нет>
```

## Правила срезов

- **Срез 1 — самый тонкий:** одно поведение без вариаций. Пример: «экспорт без фильтров, 3 колонки, кнопка скачивает файл».
- Каждый следующий срез добавляет одно поведение: «+ фильтр по статусу», «+ фильтр по датам», «+ права менеджера».
- Общая логика (схемы, хелперы) появляется внутри того среза, которому впервые нужна, а не отдельным шагом в начале.
- У каждого среза есть **Проверка: команда → ожидаемый результат**. «Ручной прогон», «проверить вручную» — не проверка; если без браузера никак, пиши e2e-сценарий или шаги со скриншотом.
- Каждый срез — отдельная сессия и отдельный коммит.

## GATES.md

Вместе с планом создай `GATES.md`: по строке на срез — команда и ожидаемый результат. Срез закрыт, только когда команда из GATES.md выполнена и результат совпал.
