# Миграция легаси: два прохода и оракул до генерации

Тесты, написанные тем же проходом, что и новый код, проверяют то, что агент придумал, а не то, что делал старый код.

## Порядок

**Проход 1 — оракул (отдельная сессия).**
1. Characterization-тесты на **старом** коде: фиксируют текущее поведение, включая странное. Странное не чинить — записать в отчёт.
2. Все тесты зелёные на старом коде.
3. Мутационная проверка тестов: внести 5–10 мелких поломок в старый код (поменять знак, границу, формат, убрать ветку) — хотя бы 80% должны ронять тесты. Если инструмент есть (Stryker и т. п.) — им. Нет — вручную, по одной, с откатом.
4. Коммит: тесты + список мутаций с результатом.

**Проход 2 — миграция (новая сессия).**
- Тесты из прохода 1 только на чтение. Если тест мешает, остановиться и спросить, а не править его.
- `@ts-ignore`, `eslint-disable`, `skip` — нельзя.

## Готово, когда

- все тесты прохода 1 зелёные без изменений;
- в мигрированном модуле нет импортов старой библиотеки;
- если библиотека больше нигде не используется — она удалена из манифеста; если используется — список мест в отчёте;
- расхождения поведения перечислены в отчёте с решением по каждому.

## Если просят «за один заход»

Один заход — да, один проход — нет: два коммита в одном запуске. Тесты прохода 1 коммитятся до первой правки модуля.
