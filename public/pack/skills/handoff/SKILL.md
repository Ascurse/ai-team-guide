# handoff — портативный саммари сессии для передачи

Пишет готовый текст-саммари текущей сессии для вставки в новую сессию Claude Code / Codex или другой AI —
прямо в этом ответе и в файл, без обращения к `/compact`.

## ВАЖНО: это не /compact

`/compact` сжимает контекст харнесса молча, без видимого текстового вывода — сама компакция не может
выполняться скиллом (это операция харнесса). `handoff` — обычный ход ассистента: пишет текст саммари
напрямую в ответ и сохраняет файлом. Компаньон `pack` собирает строку-инструкцию для `/compact` — это
другой механизм, они не взаимозаменяемы. `handoff` также не заменяет `doc-system` — тот документирует
архитектуру и решения проекта на постоянной основе, `handoff` — разовый снимок текущей сессии.

## Шаги

1. Задай два уточняющих вопроса за один шаг — в Claude Code вызови **AskUserQuestion** одним
   вызовом с обоими вопросами; в харнессах без такого тула (например, Codex) задай их обычным
   текстовым сообщением с пронумерованными вариантами:
   - `Destination` — «Куда уходит хэндофф?» — опции: **Новая сессия в этом же харнессе**,
     **Другой AI / инструмент**, **Не уверен / могут быть оба**
   - `Mode` — «Что приоритезировать в содержимом?» — опции: **Continue task**,
     **Ask a question**, **Debug session**, **Review handoff**
2. Собери текст саммари по структуре полей выбранного Mode (см. таблицу ниже), учитывая ограничение
   Destination (см. ниже). Если выбрано «Не уверен / могут быть оба» — пиши как для «Другой AI»: это
   безопасный супернабор, самодостаточный текст одинаково годится и для новой сессии Claude Code / Codex, и
   для стороннего инструмента.
3. Вывод всегда идёт по обеим схемам сразу, без дополнительного вопроса:
   - Кодовый блок с текстом саммари прямо в ответе.
   - Тот же текст файлом в scratchpad-директорию текущей сессии — путь и имя см. в разделе «Файл».
4. Одна строка после блока: что выбрано (Destination + Mode) и путь к сохранённому файлу.
5. Ничего больше не делай — не запускай `/compact`, не редактируй файлы проекта, не зови другие скиллы.

## Mode-структуры (что включать)

- **Continue task** — текущая задача; какие файлы уже тронуты и зачем; что работает, что сломано;
  следующий шаг.
- **Ask a question** — точный вопрос на решение; скорректированные findings; референс-файлы;
  констрейнты. По умолчанию пиши нейтрально, без готового ответа или рекомендации автора сессии —
  свои выводы включай, только если это явно попросили в аргументах вызова скилла.
- **Debug session** — симптом; шаги воспроизведения; что уже проверено и отвергнуто; текущая
  гипотеза; из логов — только релевантные строки.
- **Review handoff** — что сделано; какие файлы изменены и почему; какие тесты гоняли и с каким
  результатом.

## Что обязано быть в любом Mode: контракт

Поверх полей выбранного Mode текст всегда несёт **незакрытые обязательства** — что осталось
сделать, каким маршрутом, куда пишется вывод, в каком формате, что за границей допустимого.
Причина: восстановление данных не равно восстановлению контракта — прогон, восстановивший все
256 отображений кодбука после семи компакций, не восстановил ни маршрут, ни путь вывода, ни правила
сериализации. А то, что не передано явно, теряется целиком: 106 из 108 сводок компакции несли 0 из
10 контрольных фактов, по принципу «всё или ничего».
(Q15/Q9, `~/Documents/AI_workflow_research/frontend_ai_skills/synthesis/claims.md:466,472`.)

Отсюда же — почему хэндофф идёт файлом, а не только текстом в ответе: доставка на стороне харнеса
(файл, который перечитывают) работает, а расчёт на то, что принимающая сторона сама вспомнит, — нет
(Q8, `claims.md:465` — 0 обращений к памяти за 114 ходов при засеянном хранилище).

## Destination-ограничение

- **Новая сессия в этом же харнессе** — можно ссылаться на пути к файлам, названия скиллов, память; не
  нужно инлайнить содержимое файлов целиком.
- **Другой AI / инструмент** (и «Не уверен») — у получателя нет доступа к файлам, памяти, MCP-тулам
  текущего харнесса. Инлайни всё нужное (код, конфиг, конкретные находки) прямо в текст — никаких
  голых путей или названий скиллов без пояснения того, что там лежит.

## Файл

Путь: `<scratchpad/temp-директория текущей сессии>/handoff-<mode-slug>.md`, где `<mode-slug>` —
одно из: `continue-task`, `ask-a-question`, `debug-session`, `review-handoff`. Если харнесс не
даёт выделенной scratchpad-директории (например, Codex) — сохрани в `.tmp/` от текущей рабочей
директории (создай, если её нет); при желании добавь `.tmp/` в `.gitignore`, если репозиторий
под git.

## Не входит в скоуп

- Не запускает `/compact` — для инструкции туда используй `pack` (`/compact` есть и в Claude Code, и в Codex).
- Не документирует архитектуру проекта на постоянной основе — для этого `doc-system`.

## Кросс-агентная установка самого скила

Скил живёт в двух местах с **идентичным** содержимым (формат `SKILL.md` у Claude Code и Codex
совпадает): `~/.claude/skills/handoff/` (Claude) и `~/.agents/skills/handoff/` (Codex). Обе копии
ставит `install.sh` из kit; канон — `core/skills/handoff/` в kit, правь там и переустанавливай, а не
каждую копию руками.
